# Архитектура

Backend использует Go: `net/http` для HTTP, `log/slog` для логов, pgx/v5 для PostgreSQL. Точка входа `backend/cmd/shorter` собирает зависимости, проверяет соединение с БД и запускает HTTP-сервер. При остановке сервер завершает активные запросы перед закрытием пула.

Go-модуль и Dockerfile находятся в `backend`; пути пакетов и импорты `shorter/...` сохранены. `frontend` содержит независимый npm-проект на JavaScript, React и Vite. SQL-миграции остаются в корневом `migrate`, общие Compose и Makefile — в корне.

Структура Ports & Adapters внутри backend:

- `backend/core/models` — модель Link; `backend/core/ports` — интерфейсы хранилища, генератора кода и сокращения ссылки.
- `backend/core/services` — проверка URL, создание кода, сохранение и повтор при коллизии, проверка кода и получение исходного URL; ядро не зависит от адаптеров.
- `backend/core/errors` — ошибки ядра, импортируемые как `cerrors`.
- `backend/adapters/handlers` — HTTP и JSON, локальные DTO в `dto`.
- `backend/adapters/repositories/postgres` — параметризованные INSERT и SELECT по первичному ключу через pgx, без управления схемой. `pgx.ErrNoRows` преобразуется в `ErrLinkNotFound` ядра.
- `backend/adapters/codegen` — генерация 9 случайных байт через crypto/rand, кодирование в 12 символов base64url.
- `migrate` — версионированные SQL-файлы up/down, применяемые golang-migrate отдельно от backend.

Принятое хранилище — PostgreSQL (заменяет первоначальный ориентир in-memory). Таблица `links` хранит `code` (первичный ключ) и `original_url`. Схему создаёт миграция `migrate/000001_create_links.up.sql`, откат описан в соответствующем `.down.sql`. Применённую версию и dirty-состояние учитывает golang-migrate в `schema_migrations`; движок блокирует конкурентное применение миграций. Backend не выполняет DDL.

Первая миграция допускает существование совместимой таблицы из ранней реализации, сохраняя строки. Произвольные отличия старой схемы не исправляются автоматически. Откат первой миграции удаляет таблицу и её данные. Изменения схемы добавляются следующими нумерованными файлами; применённые миграции не переписываются.

Уникальность кода обеспечивается атомарным `INSERT ... ON CONFLICT (code) DO NOTHING`. Нулевое количество вставленных строк преобразуется в ошибку конфликта ядра. Сервис делает до пяти попыток; успешный ответ возможен только после сохранения. Один URL можно сократить несколько раз.

Маршруты: `GET /healthz` проверяет HTTP-процесс; `POST /api/links` создаёт ссылку; `GET /{code}` возвращает 302 с исходным URL в `Location`. Последний маршрут также поддерживает HEAD по правилам `net/http`. Формат кода проверяет сервис, отсутствие записи даёт 404, неверный код — 400, сбой чтения — 500. Чтение доступно через отдельный порт `LinkResolver`. Настройка `BASE_URL` задаёт публичный префикс; допускается префикс пути, но без query, fragment и credentials. При префиксе пути обратный прокси должен удалять его перед передачей запроса backend. Таймаут операций сокращения и получения — 5 секунд; ошибки зависимостей не раскрываются HTTP-клиенту. Подробности: [лог перехода по ссылке](logs/0008-resolve-short-link.md).

Сервис проверяется Table-Driven тестами с gomock, репозиторий — с pgxmock, обработчик — через httptest и gomock. `make generate` генерирует моки портов закреплённым в go.mod инструментом mockgen. `make check` запускает тесты, race detector и vet; все три обязательны перед коммитом.

Dockerfile собирает статический Go-бинарник в отдельном этапе и запускает его в Alpine от непривилегированного пользователя. Compose запускает PostgreSQL 17, одноразовый контейнер `migrate/migrate:v4.19.1` и backend. Мигратор ждёт готовности PostgreSQL через `pg_isready`, backend — успешного завершения мигратора (`service_completed_successfully`). Ошибка миграции блокирует запуск backend. SQL монтируется в мигратор только для чтения; в образ приложения не включается.

Для базы используется именованный том; порт на хост не публикуется. Backend и мигратор получают согласованные PG-переменные из общего блока Compose. Мигратор использует PostgreSQL-драйвер своего CLI и права на DDL; приложение продолжает работать через pgx. Для локального MVP используется один пользователь, но права CREATE backend больше не нужны для его кода.

Frontend содержит одну форму: проверка HTTP(S) URL, `POST /api/links`, отображение `short_url`, копирование и переход. Нет истории, авторизации и клиентского роутера. При ошибке HTTP, сети или таймауте показывается сообщение, повторная отправка во время запроса заблокирована. Невозможность копирования оставляет ссылку выделенной для ручного копирования.

Compose дополнительно собирает frontend на Node.js 24 и запускает nginx на `127.0.0.1:3000`. nginx отдаёт `/` и `/assets/`, остальные запросы передаёт backend, включая `/api/links`, `/healthz` и короткие адреса. `BASE_URL` в Compose по умолчанию указывает на `http://localhost:3000`; прямой запуск Go сохраняет прежнее значение `http://localhost:8080`. Vite для разработки проксирует API, healthz и 12-символьные коды на `127.0.0.1:8080`. Запросы frontend идут к своему origin, поэтому изменения CORS в backend не нужны.
