# BUG-003: диапазон порта URL

Задача: одинаково проверять порт исходного URL и BASE_URL, отклонять значения вне допустимого диапазона до генерации кода и сохранения ссылки.

Статус: реализовано и проверено в `fix/url-port-validation` от `dev`, готово к пользовательскому review.

Решение: указанный порт должен быть числом 1–65535. Порт 0 и пустой порт после двоеточия отклоняются; отсутствие порта разрешено, включая IPv6. Ведущие нули допустимы в числовом значении. Проверка доступности адреса не выполняется. Альтернатива с разрешённым портом 0 не выбрана: нулевой порт не обозначает прикладную HTTP-службу назначения.

Результат: общий parseURL использует ParseUint с пределом 16 бит, отклоняет 0 и пустой порт. Это исправляет одновременно Shorten и конструктор BASE_URL, не меняя сохранённое представление ссылки.

Воспроизведение: новые Table-Driven тесты на исходном коде падали для 65536, 99999, слишком длинного числа, 0 и пустого порта, включая IPv6: конструктор принимал BASE_URL, сервис вызывал генератор вместо отказа. После исправления те же тесты проходят. Gomock подтверждает отсутствие вызовов генератора и репозитория для невалидных URL. HTTP-тест с реальным LinkService проверяет 400 и JSON-ошибку для невалидных портов и 201 для 65535.

Проверки: gofmt, `go test ./... -cover`, `go test -race ./...`, `go vet ./...`, `git diff --check` — успешно. Покрытие сервисов, обработчиков и PostgreSQL-репозитория — 100%. Слияние в dev ожидает review; другие BUG-задачи в ветку не включены.
