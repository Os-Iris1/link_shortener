# Создание короткой ссылки

- Задача: реализовать получение URL, запись в PostgreSQL и возврат короткой ссылки.
- Принято пользователем: Ports & Adapters с `core/models`, `core/ports`, `core/services`, `core/errors`; ошибки ядра импортируются как `cerrors`; адаптеры в `adapters`; HTTP через net/http, PostgreSQL через pgx; табличные тесты сервисов и репозиториев с gomock и pgxmock, Makefile; обязательные тесты, race и vet перед коммитом.
- Контракт реализации: `POST /api/links`, JSON `url`, ответ 201 с `short_url`; только абсолютные HTTP(S) URL; BASE_URL задаёт публичный адрес. Редирект не входит в эту итерацию.
- Критерии готовности: корректный URL записывается и возвращается короткий адрес; ошибочный запрос даёт 400, ошибка хранилища — 500; коллизии кодов обрабатываются без перезаписи; сервис и репозиторий покрыты табличными тестами; проверки test/race/vet и проверка на PostgreSQL выполнены.
- Решение: криптографически случайные коды, уникальный ключ PostgreSQL, повтор при коллизии; минимальная идемпотентная инициализация таблицы при старте. Ядро зависит только от портов, main собирает адаптеры и сервис.
- Альтернативы: последовательный ID раскрывает порядок создания ссылок; проверка существования кода до записи допускает гонку. Выбрана атомарная запись с уникальным ограничением.
- Зависимости: pgx v5.11.0 несовместим с pgxmock v4.9.0 из-за нового метода Rows.TypeMap. После проверки сборки зафиксирован pgx v5.10.0, совместимый с используемым pgxmock; gomock/mockgen v0.6.0.
- Статус: реализовано и проверено.
- Ограничения: редирект и расширенное управление миграциями не входят в задачу. До первого коммита dev отсутствует; существующий индекс пользователя сохраняется, коммит не создаётся автоматически.
- Результат: добавлены core и adapters, endpoint, pgxpool, начальная схема, безопасная параметризованная запись и повтор при коллизиях; настроен BASE_URL. Добавлены табличные тесты сервисов (gomock), репозитория (pgxmock) и обработчика (httptest/gomock), генерация моков и Makefile. Обновлены Dockerfile, README, продуктовая и архитектурная документация, VERSIONS.md. В AGENTS.md и навыке shorter-go закреплены обязательные проверки перед коммитом.
- Unit-проверки: финальный `make check` выполнил `go test ./... -cover`, `go test -race ./...`, `go vet ./...` успешно. Покрытие операторов сервиса, репозитория и HTTP-обработчика — 100%; это не покрытие всего приложения. Проверены ошибки зависимостей, коллизии и исчерпание попыток, отмена контекста, валидация URL и BASE_URL, ошибки JSON/Content-Type/размера запроса, скрытие внутренних ошибок. Навык shorter-go прошёл quick_validate.py.
- Интеграционные проверки: Compose config и сборка backend успешны. На настоящем PostgreSQL `POST /api/links` вернул 201, возвращённый код найден в БД с точным исходным URL. Ошибочный URL вернул 400, количество строк не изменилось. После `down` и повторного `up --wait` сервер готов, запись сохранилась. После проверки контейнеры остановлены, том сохранён (в нём остаётся проверочная запись).
- Проверка изменений: `git diff --check` без ошибок. Коммит и внешняя отправка агентом не выполнялись.
- Следующий приоритет: согласовать отдельную задачу перехода по коротким ссылкам; следующий этап автоматически не начинается.
