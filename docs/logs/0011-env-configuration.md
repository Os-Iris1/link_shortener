# CFG-001: конфигурация окружения

Задача: убрать пароль по умолчанию из Compose, добавить безопасный шаблон `.env.example`, описать настройку Compose и прямой запуск Go. Существующий `.env` и рабочие данные сохраняются.

Решение: штатная загрузка `.env` средствами Compose, обязательная непустая переменная `POSTGRES_PASSWORD` в обоих местах использования. Backend и мигратор получают общие PG-переменные. Frontend не получает параметры БД. Собственный dotenv-парсер и внешнее хранилище секретов не добавляются.

Обоснование: проверка `${VAR:?...}` останавливает Compose до запуска контейнеров; передача пароля через окружение PG исключает необходимость URL-кодирования. Альтернатива с паролем в URL не нужна и усложняет поддержку специальных символов.

Статус: реализовано в отдельной ветке `chore/env-configuration`; требуется пользовательский code review перед слиянием в `dev`.

Результат: добавлен `.env.example` без пароля; обязательное значение проверяется в обоих местах Compose. Расширены `.gitignore` и оба `.dockerignore` для `.env.*`; шаблон доступен для добавления в Git. README описывает первоначальную настройку в shell и PowerShell, одинарные кавычки для `$`, `#` и экранирования кавычки, приоритет окружения, PG-переменные прямого запуска и существующие тома. Go-код и схема БД не менялись. Добавлен воспроизводимый `scripts/test-env.ps1` с отдельным именем проекта, портом, томами и очисткой тестовых ресурсов.

Успешные проверки:

- `go test ./... -cover`, `go test -race ./...`, `go vet ./...` из `backend`.
- `docker compose config --quiet`; отсутствующий и пустой пароль отклоняются до запуска. Через JSON конфигурации проверены согласованность DB/user/password и приоритет окружения, отсутствие окружения БД у frontend. Вывод с паролями не публикуется. Учтено, что `config` удваивает буквальный `$` для повторного чтения конфигурации.
- `scripts/test-env.ps1 -CopyMigrations`: сборка backend и frontend, PostgreSQL healthy, успешная миграция версии 1, повторный up, healthz 200, создание ссылки 201, редирект 302 с точным query/fragment. Тестовый пароль содержит `$`, `#`, пробел и одинарную кавычку. Переменная BASE_URL из оболочки переопределяет файл и подтверждается реальным ответом API.
- `git check-ignore`: `.env` и локальные варианты в корне/backend/frontend игнорируются, `.env.example` не игнорируется; `git diff --check` успешен.

Ограничение среды: штатный bind mount каталога миграций с диска D: зависает при создании контейнера Docker Desktop; отдельная проба подтверждает проблему монтирования. Тестовые процессы остановлены, ресурсы очищены. Поэтому интеграционная проверка использует явный `-CopyMigrations`: те же SQL-файлы копируются через Docker API в отдельный Docker-том. Это проверяет конфигурацию и полный сценарий приложения, но не подтверждает работоспособность штатного bind mount на этом хосте. Основной Compose-файл сохраняет штатное read-only монтирование.

При отладке тестового скрипта выяснилось, что Docker меняет автоматически назначенный порт при перезапуске контейнера. Итоговый скрипт выбирает свободный порт заранее и сразу задаёт BASE_URL; пересоздание backend не требуется. Рабочий `.env` не создавался и не изменялся; рабочие тома, `stage` и удалённые серверы не затрагивались. `docs/tasks.md` остаётся локальным игнорируемым планом согласно сохранённому `.gitignore`; статус CFG-001 в нём обновлён.
