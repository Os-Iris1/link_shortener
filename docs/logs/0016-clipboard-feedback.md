# BUG-005: видимый результат копирования

Задача: показать сообщение об отказе Clipboard API обычному пользователю, сохранив уведомление скринридера, фокус и выделение короткой ссылки.

Статус: реализовано и проверено в `fix/clipboard-feedback` от `dev`, готово к пользовательскому review.

Решение: существующая область role=status становится видимой при появлении copyMessage. Сообщение готовности ссылки остаётся доступным скринридеру без дополнительного визуального текста. Успех и ручное копирование используют одну область, сброс сохраняется в начале следующего сокращения.

Результат: сообщение копирования отображается под полем результата, role=status и aria-atomic сохраняют доступность. Поведение focus/select не менялось. README обновлён.

Воспроизведение: браузерный сценарий Edge на исходном коде обнаружил область сообщения 1×1 px с clip-path inset(50%). После исправления тот же сценарий прошёл для отсутствующего Clipboard API, отклонённого writeText и реального успешного копирования с проверкой содержимого буфера. Проверены запуск кнопки через Enter, фокус и полное выделение при отказе, сброс уведомления при новом сокращении, отсутствие JS-ошибок и горизонтальной прокрутки на ширине 375 px. Снимки сохранены во временной QA-папке вне ветки. Наличие live region проверено браузером; отдельная ручная проверка скринридером не проводилась.

Проверки: `npm ci --offline`, `npm run build`, браузерный сценарий Edge/Playwright, `go test ./... -cover`, `go test -race ./...`, `go vet ./...`, `git diff --check` — успешно. Отдельный вспомогательный скрипт в репозиторий не добавляется. Слияние ожидает review.
