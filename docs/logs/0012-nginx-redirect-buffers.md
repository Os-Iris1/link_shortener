# BUG-001: длинные Location через nginx

Задача: воспроизвести 502 на предельном URL и согласовать буферы nginx с лимитом приложения 8192 байт, включая percent-encoding Unicode.

Статус: исправление реализовано и проверено в `fix/nginx-redirect-buffers` от `dev`, готово к пользовательскому review.

Решение: буфер заголовка 32 KiB вмещает Location до 24576 байт после кодирования и служебные заголовки; размеры буферов тела и занятых буферов согласуются с ним. Контракт API и лимит исходного URL сохраняются. Проверка HTTP через реальный nginx оформляется Go-тестом с явно заданным адресом изолированного стенда.

Реализованы `proxy_buffer_size 32k`, `proxy_buffers 4 32k`, `proxy_busy_buffers_size 64k`. Отключение буферизации не выбрано: оно не снимает ограничение буфера заголовка. Основание: [документация nginx](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_buffer_size).

Добавлен Table-Driven `TestLongRedirects`: ASCII/Unicode ровно 8192 байт, GET/HEAD и точный Location, query/fragment, 400 для 8193 байт. Запуск через `SHORTER_TEST_PROXY_URL` описан в README; отдельный orchestration-скрипт не включается в репозиторий.

Первоначальная проверка: `go test ./... -cover`, `go test -race ./...`, `go vet ./...` прошли; интеграционный тест без адреса стенда был явно пропущен. Загрузка образов завершалась EOF при TLS-соединении с registry-1.docker.io. Ограничение интеграционной проверки снято следующим прогоном.

После восстановления окружения поднят отдельный Compose-проект с тестовой БД и портами на уже собранных образах приложения (nginx 1.30.6). Повторная сборка в новой рабочей копии дала ошибку BuildKit; приложение в этих ветках не менялось, поэтому исходная и исправленная конфигурации последовательно загружались только в тестовый nginx. SQL использовался из неизменённого корневого migrate через штатный путь монтирования; рабочая БД не затрагивалась.

Исходная конфигурация: POST 201, затем GET/HEAD 502 для ASCII и Unicode длиной 8192 байт; журнал nginx подтвердил `upstream sent too big header`. Исправленная конфигурация: POST 201, GET/HEAD 302 с точным Location, включая query/fragment; длина Unicode Location — 24504 байта. Уточнено ожидаемое представление percent-encoding в тесте: net/http использует строчные шестнадцатеричные цифры. URL 8193 байта получил 400; отдельный подсчёт строк подтвердил отсутствие записи (6 до и 6 после запроса). `nginx -t` прошёл.

Финальные проверки: интеграционный тест с реальным nginx, `go test ./... -cover`, `go test -race ./...` (включая интеграционный тест), `go vet ./...` и `git diff --check` — успешно. Ветка не слита в dev.
