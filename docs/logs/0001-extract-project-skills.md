# Выделение проектных skills

- Задача: разложить инструкции `AGENTS.md` на навыки в `.codex/skill`.
- Цель и границы: перенести существующие правила без изменения продукта и стека; оставить общий контекст и маршрутизацию в `AGENTS.md`.
- Критерии готовности: три самостоятельных `SKILL.md` с метаданными; ссылки из `AGENTS.md`; сохранение читаемых требований; проверка структуры навыков.
- Предложенное решение: выделить итерации, документацию и версии, разработку и проверки Go.
- Статус решения: реализовано и проверено структурно в рамках запроса пользователя.
- Обоснование: инструкции загружаются по задаче; обязательные общие правила остаются в корневом файле. Путь `.codex/skill` выбран пользователем, чтение обеспечивается прямыми ссылками, автоматическое обнаружение не проверено.
- Альтернатива: оставить весь текст в `AGENTS.md`; это сохраняет постоянную загрузку подробностей для любых задач.
- Ограничение исходника: последний раздел содержит буквальные `?`. Переносим однозначно читаемые требования; точный смысл скобочного фрагмента о unit-тестах и части архитектурных формулировок восстановить нельзя. Новые требования из них не выводим.
- Результат: созданы `shorter-iteration`, `shorter-documentation`, `shorter-go`; `AGENTS.md` сокращён до общих правил и маршрутизации. Создана запись `Unreleased` в `VERSIONS.md`.
- Проверки: `quick_validate.py` выполнен отдельно для каждого из трёх навыков — все прошли. Проверено существование целевых файлов ссылок из `AGENTS.md` и лога. Инструкции сопоставлены с читаемыми правилами исходника.
- Ограничения: автоматическое обнаружение в `.codex/skill` и поведенческое применение в новой сессии не проверялись; предусмотрено явное чтение через `AGENTS.md`. Go-проверки не запускались: код приложения отсутствует, изменена только документация.
- Следующий приоритет: уточнить утраченные формулировки исходного раздела о Go при появлении исходника без повреждений.
