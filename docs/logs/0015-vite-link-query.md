# BUG-004: query коротких ссылок в Vite

Задача: передавать backend короткую ссылку с query в dev и preview, сохраняя исходные параметры и исключая лишний сегмент пути.

Статус: реализовано и проверено в `fix/vite-link-query` от `dev`, готово к пользовательскому review.

Решение: после 12 символов кода разрешить конец строки или начало query. Регрессию проверить через реальные dev/preview серверы с тестовым backend и конфигурацией приложения; отдельная копия регулярного выражения в тесте не используется.

Результат: изменён один ключ общего proxy-словаря dev/preview. Добавлен `vite.config.test.js` на встроенном node:test и команда `npm run test:proxy`. Тест импортирует конфигурацию приложения и меняет только адрес назначения на временный backend. Сборка, кеш и HTTP-порты изолированы; новые зависимости не нужны.

Воспроизведение: на исходном коде оба сервера возвращали HTML 200 вместо редиректа 302 уже для `/abcdefghijkl?`. После исправления проходят GET/HEAD без query, с пустым query, одним/несколькими параметрами и percent-encoded значениями. Vite нормализует одиночный пустой `?` в отсутствие query; параметры с содержимым передаются побайтно. Лишний сегмент и неверная длина кода остаются frontend-маршрутами; API, healthz и HTML проверены.

Проверки: `npm ci --offline`, `npm run test:proxy` (dev и preview), `npm run build`, `go test ./... -cover`, `go test -race ./...`, `go vet ./...`, `git diff --check` — успешно. Ветка не слита в dev.
