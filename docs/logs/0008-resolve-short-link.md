# Получение ранее сокращённой ссылки

Задача: добавить чтение сохранённой ссылки, обработать ошибки стандартными HTTP-кодами и проверить запущенное приложение до пользовательского review.

Статус: реализовано и проверено, передано на пользовательское review в ветке `feature/resolve-short-link` от `dev`. Одобрение и слияние ещё не выполнены.

Решение: пользователь подтвердил `GET /<код>` → `302 Found`. Добавлено чтение PostgreSQL по коду через порт репозитория и сервис; исходный URL возвращается в `Location` целиком. Отсутствие записи отделено от сбоя хранилища. Схема не меняется. Рассмотренная альтернатива — JSON API с исходным URL — не выбрана.

Результат: проверка 12 символов base64url в сервисе; неверный код — 400, неизвестный — 404, ошибка чтения — 500 без внутренних подробностей. HEAD поддерживается без тела, остальные методы дают 405 с Allow. Чтение ограничено 5 секундами. Обновлены README, продукт, архитектура и Unreleased.

Проверки:

- `make generate` — успешно, моки обновлены.
- `make check` — успешно: `go test ./... -cover`, `go test -race ./...`, `go vet ./...`. Покрытие handlers/services/repositories — 100%; codegen и точка входа не имеют unit-тестов.
- Table-Driven тесты сервиса с gomock и репозитория с pgxmock: успешное чтение, отсутствие записи, сбой БД, отмена/таймаут контекста, неверный код, ошибка чтения строки; HTTP-тесты проверяют статусы, Location, HEAD, Allow и отсутствие внутренних подробностей.
- Первый прогон выявил ошибочное ожидание, что pgxmock даст ошибку при чтении NULL в строку. Имитация заменена явной ошибкой строки; повторный полный прогон успешен.
- `docker compose up --build -d` — успешно, мигратор завершился с кодом 0, backend запущен.
- На запущенном приложении: healthz 200; POST создаёт ссылку с 201; GET даёт 302 с точным исходным URL (query и fragment сохранены); HEAD — 302 без тела; неверный код — 400; неизвестный — 404; POST короткого адреса — 405 с Allow; корень и лишний сегмент — 404.
- PostgreSQL временно остановлен: чтение дало 500 с общим JSON-сообщением. PostgreSQL восстановлен, повторный GET дал 302, сохранённая ссылка осталась доступна.
- `git diff --check` — успешно.

Окружение Docker Compose оставлено запущенным для review на `http://localhost:8080`. Тестовая ссылка: `http://localhost:8080/2Lo_dSp_gBNX` → `https://example.com/path?q=1&x=2#part`.

Ограничения: маршруты backend находятся в корне; при префиксе пути BASE_URL обратный прокси должен удалять префикс. Расширение модели (срок жизни, удаление, пользовательские коды) не входило в задачу. После review и одобрения пользователя требуется последний запуск перед слиянием в dev.
