# Разделение backend и frontend

Задача: изучить документацию, разделить сервер и клиент по папкам и добавить минимальный frontend на JavaScript и React.

Статус: реализовано и проверено в ветке `feature/backend-frontend` от `dev`, подготовлено к пользовательскому code review. Слияние в `dev` не выполнялось.

Решение: Go-модуль, `cmd`, `core`, `adapters` и серверный Dockerfile перенести в `backend`. SQL оставить в корневом `migrate` согласно правилам проекта. В `frontend` разместить React с Vite, форму сокращения URL, результат, копирование и обработку ошибок. Compose запускает frontend через nginx с проксированием API и редиректов в backend. Документация и общие команды остаются в корне.

Обоснование: независимые зависимости и сборки клиента и сервера; существующие Go-импорты и HTTP API сохраняются. Альтернатива с переносом миграций в backend отклонена из-за требования хранить `migrate` в корне. Авторизация, история и управление ссылками не входят в задачу.

Результат: Go-модуль перенесён без изменения исходного кода и импортов. Общий Makefile выполняет Go-команды из backend; добавлены команды frontend. React-форма адаптирована для мобильной ширины, показывает загрузку и ошибки, блокирует повторную отправку, поддерживает копирование с выделением результата при отказе буфера обмена. Обновлены README, архитектура, продукт и Unreleased. Зависимости React/Vite закреплены точными версиями и npm lock-файлом.

Проверки:

- `make check` — успешно: `go test ./... -cover`, `go test -race ./...`, `go vet ./...`. Покрытие handlers/services/repositories — 100%.
- `npm run build` из frontend — успешно.
- `docker compose config --quiet` и `docker compose up --build -d` — успешно; frontend собирается через `npm ci`, мигратор завершился с кодом 0, PostgreSQL healthy, backend и nginx запущены.
- `docker compose exec -T frontend nginx -t` — успешно.
- Проверка в установленном Edge через временный Playwright-скрипт: рендер React; реальный POST через nginx с 201; GET короткого URL с 302 и точным Location, включая query/fragment; открытие ссылки; копирование в буфер; выделение при отказе буфера; клиентская проверка URL с credentials; HTTP 500 и сетевой сбой; состояние загрузки и блокировка повторного запроса. Ошибок JavaScript нет.
- Проверены скриншоты desktop и мобильной ширины 375 px, горизонтальной прокрутки нет. Временные инструменты и скриншоты находятся вне репозитория.
- `npm run dev`: Vite запущен, проверены HTML 200, healthz 200, POST через proxy с 201 и редирект через proxy с 302 и точным Location; временный dev-сервер остановлен после проверки.
- `git diff --check` — успешно.
- Первые прогоны npm/Go и Git/Docker были ограничены песочницей; после расширения доступа проверки выполнены успешно.

Окружение Compose оставлено работающим для review: `http://localhost:3000`. Backend доступен напрямую на `http://localhost:8080`. В Compose публичный `BASE_URL` по умолчанию изменён на адрес nginx (3000); существующий `.env` может переопределить его. При разработке только через Vite задавайте `BASE_URL=http://localhost:5173` перед запуском backend через Compose. Схема и содержимое миграций не менялись.

Ограничения: отдельные unit-тесты frontend не добавлялись, интерфейс проверен браузерными сценариями. Временный браузерный скрипт не входит в репозиторий. История, авторизация, управление ссылками и публикация не входят в задачу.
