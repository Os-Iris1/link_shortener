# Правила работы над Shorter

Проект: сокращатель ссылок. Рабочий язык общения и документации — русский.

## Общие правила

- Каждую задачу выполняем в отдельной ветке от `dev`. После реализации запускаем необходимые проверки и передаём изменения пользователю на code review. Слияние ветки задачи в `dev` выполняем только после явного разрешения пользователя. Накопленные изменения продвигаем из `dev` в `stage` для указанной пользователем версии только после глобального review и разрешения пользователя; локальная операция не разрешает отправку на удалённый сервер.
- Перед каждым коммитом обязательно успешно выполнить `go test ./... -cover`, `go test -race ./...` и `go vet ./...` (или `make check`, выполняющий эти команды). Если проверка недоступна или не проходит, коммит не создавать. Сервисы и репозитории покрываем Table-Driven unit-тестами с gomock и pgxmock соответственно.
- Разрешения действуют во всех чатах по проекту: команды Docker и Docker Compose, а также команды Git без взаимодействия с удалёнными серверами разрешены в рамках текущей задачи без повторного согласования. Можно собирать образы, запускать и останавливать контейнеры, выполнять `git add`, создавать локальные коммиты, создавать и удалять локальные ветки.
- Git не должен взаимодействовать с удалёнными серверами: запрещены `git push` (включая ветки и теги), `git fetch`, `git pull` и другие сетевые операции Git. Перед Git-операциями прочитай навык `shorter-git`.
- Разрешения пользователя не отменяют ограничения среды: если Docker или локальный Git заблокированы песочницей, запрашивай расширенный доступ для конкретной команды через механизм выполнения инструментов; не считай это отсутствием разрешения пользователя на саму операцию.
- Соблюдаем границы выбранной задачи; не начинаем следующий этап без согласованной цели.
- Предложение агента само по себе не является согласованным требованием.
- При начале содержательной задачи создаём запись в `docs/logs/NNNN-short-topic.md` и обновляем по мере работы. Для небольшой правки достаточно краткой записи.
- Документацию обновляем вместе с соответствующим изменением. В итоговом отчёте указываем результат, фактически выполненные проверки и существенные ограничения.

## Проектные навыки

Перед соответствующей работой прочитай указанный `SKILL.md`. Для задачи могут понадобиться несколько навыков. Пути отсчитываются от корня репозитория.

- [shorter-iteration](.codex/skill/shorter-iteration/SKILL.md) — планирование и завершение MVP, спринтов и Next Stage.
- [shorter-documentation](.codex/skill/shorter-documentation/SKILL.md) — логи содержательных задач, требования, архитектурные решения, сводка версий и сообщения коммитов.
- [shorter-go](.codex/skill/shorter-go/SKILL.md) — реализация и проверка Go-приложения, архитектуры и контейнерного запуска.
- [shorter-git](.codex/skill/shorter-git/SKILL.md) — локальная работа с ветками `dev`, `release`, `stage` по Gitflow и коммиты Conventional Commits; отправка на удалённый сервер запрещена.

Навыки хранятся в `.codex/skill` по указанному пользователем пути; используй прямые ссылки выше независимо от автоматического обнаружения навыков клиентом.
